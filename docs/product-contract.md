# GitHub Agent Channel 产品契约

GitHub Agent Channel 是个人与团队委派、持续协作和核验自有 Agent 工作的通道。用户在多个仓库中发起任务，在原 Issue 或 PR 查看进展、提出修改并核验成果。本文规定成熟版验收目标；当前实现见[能力台账](capabilities.md)，选型依据见[调研记录](product-research-20261124.md)。

## 通道承诺

| 编号 | 能力 | 验收条件 |
| --- | --- | --- |
| C1 | 接入 | 按仓库选择 Agent、权限与事件；执行机只需出站。撤销一个仓库不影响另一个。能区分未安装、漏订阅、投递失败和执行端离线；重复投递、补投及处理结果可查，证据不足时不猜原因。 |
| C2 | 委派 | 分析任务不改代码；只读 Agent 收到编码请求时明确拒绝，不自行换用更高权限身份。 |
| C3 | 上下文 | 只读任务获准访问的仓库、线程和版本；PR 按实际 base/head 取差异，材料缺失或截断须明示。Issue、评论、fork、提交、文件和 CI 输出都是任务数据，其内容不能扩大权限或改变策略。 |
| C4 | 续办 | Channel 的任务记录保留约束，并关联 Issue、PR 和后续指令。更换 Runtime 会话后仍可续办；不同仓库的同号 PR、无关线程不得串线。 |
| C5 | 干预 | 用户能在 GitHub 查看任务状态、回答澄清、请求停止或接管；Channel 按下表报告可核验的状态。 |
| C6 | 成果 | 从原任务可追到运行和实际成果。编码任务关联实际改动、提交 SHA、PR head、验证对象与结果、对应版本的 CI / Review（如有），以及发布操作与回执。模型自述不算验证；纯分析不要求 commit 或 PR，仓库任务不虚构评论目标。 |
| C7 | 授权与重投 | 每次外部写入前校验 App 安装授权、发起人对目标资源的权限及任务操作范围。不满足时停止写入并说明原因；已有授权无需重复确认，新增授权由有权用户完成。重复投递不得重复写入；结果不明先对账，不盲目重发。 |
| C8 | 诊断与支持范围 | 管理员无需读密钥或改库即可从投递查到运行和发布结果。支持矩阵按「适配器、具体 Runtime/harness、影响行为的版本与执行环境」列出支持及不支持的工作流。每项支持声明须有该组合的真实场景、执行结果及可追溯记录，不得借用其他组合的证据。 |

### 任务状态的验收口径（C5、C6、C7）

| 用户看到的状态 | 判断依据 |
| --- | --- |
| 已接收 / 执行中 | 任务已持久化且可追踪才算接收；有执行端运行证据才报执行中。断连后无法确认是否仍在运行，报未知。 |
| 等待输入 | 说明等谁、需要什么，以及在哪里答复。 |
| 停止中 / 已停止 | Channel 接受停止请求即不再发起新发布，在途写入单独对账。只有执行端确认终止才报已停止，并说明已有改动是否保留、如何接管；无法确认终止则报未知。 |
| 已完成 / 失败 / 未知 | 达到该任务约定的完成条件才报完成。已知未达标报失败，证据不足报未知。PR 已创建但必需验证失败，应同时展示 PR 回执与验证失败，不报任务完成。 |

## 工作流与通过条件

| 编号 | 交付级别 | 通过条件 |
| --- | --- | --- |
| W1 分析 | 必需 | 在 Issue 或 PR 发问、补充约束、得到有依据的关联回复；不产生代码改动。 |
| W2 编码与续改 | 必需，首要验收 | Issue → 实际改动与验证 → draft PR → 维护者在改动行提出调整 → 更新**同一 PR**并验证新 head。无需手贴 diff 或运维切换运行时。 |
| W3 原生评审 | 正式支持，按仓库启用 | 对具体提交发布 GitHub Review；行内意见绑定文件、差异位置和版本。head 更新后，旧意见保留原版本归属；定位失效时标明过期，基于新差异复核，不复用旧行号。普通评论不计为原生 Review。 |
| W4 CI 反馈 | 状态反馈必需，自动修复可选 | 展示目标 head SHA、检查来源、链接及状态。新 head 不继承旧 SHA 的通过结论；无权限、未运行或仍在等待均不算通过。启用修复后限制轮数，重新核验新提交。 |

**W2 安全续改：** 写入前核对 PR 的 head、base 和期间新增的提交。head 上有人类新提交时，能安全接续就保留这些提交，仅在任务授权范围内追加修改；base 推进时重新判断集成条件。无法安全更新时停止写入，保留现有成果并说明冲突与接管方式。不得强推覆盖、丢弃或未经授权改写人类提交。

## 职责与变更

- Channel 管 GitHub 身份、路由、任务上下文、授权、发布与回执；Runtime 管推理与编码工具，执行设施管工作区与隔离。至少一个正式组合须跑通完整 W2；只声明分析的组合按 W1 验收。
- 全量事件监听、自动合并、企业多租户与计费、自建模型或沙箱不属于基础版门槛。ECS 是可选部署。
- 删除旧契约，不设兼容别名。遇旧库须报明不支持的格式及所需版本，原样保留，并指引用户备份旧库、另建新库；恢复备份不等于转换格式，不提供旧库迁移。
- 功能 PR 引用 C/W 编号，说明复用选择、验收条件与证据。缩减承诺或扩大权限须由产品负责人确认。API、存储结构和状态枚举由技术设计承接。
