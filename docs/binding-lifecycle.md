# 仓库绑定与授权生命周期（#9）

适用 C1/C2/C7/C8。仓库登记与设备领取已接入服务端和 CLI。见[自助接入指南](agent-self-service.md)及[跨设备 HTTP 测试](../tests/self-service-e2e.test.ts)。本地测试中的 GitHub/模型为替身。

| 安装与有效绑定 | 触发规则 | 设备 | 决策 |
| --- | --- | --- | --- |
| 无绑定、已停用或已知撤权 | 任意 | 任意 | 签名合法也不建任务 |
| 有效 | 不匹配 | 任意 | 忽略，不唤醒模型 |
| 有效 | 匹配 | 离线 | 持久入队，等待获准设备；不因离线解绑 |
| 有效 | 匹配 | 在线 | 同样先入队；领取前重新核验 |

**身份与授权。** 设备凭据只证明设备身份；首次配对须由已认证的 GitHub 用户明确批准目标设备，服务端绑定不可变的 GitHub 用户 ID。新增或更新绑定时服务端独立查询该 App 安装覆盖的 repository ID，并确认配置者当前具备该仓库 admin 权限。设备不得自报操作者或安装证明；服务管理员的凭据不可分发到客户端。首次配对申请 10 分钟失效，仅可消费一次；配对完成持续有效直至撤销，不能以配对代替之后的仓库权限复核。日常处理仍校验事件发起人的权限，启用事件不启用写仓策略。

**登记协议（命令见自助接入指南）。** 输入为仓库选择、启停、显式事件及匹配标签、预期 revision；服务端从认证会话派生设备/管理者，并解析稳定安装及仓库 ID。返回服务端修订和生效结果，不回显凭据。首次启用期望 0；实际变化使修订加一，同设备/操作者的完全相同请求可安全确认最近一次结果。版本冲突要求读取当前状态，不能自动覆盖；参数错误拒绝，授权或状态查询不可用时不批准。读取、停用也须鉴权；待同步停用不得显示为已生效。

**排他归属与撤销。** 一个 installation/repository 同时只归一个设备。离线、读取本地文件失败或重启不产生停用操作。显式停用保留修订及所有者（墓碑）；普通登记不能抢占墓碑。设备丢失或需要换机时，先撤销旧设备凭据并封锁旧租约/发布，核对在途写入，再由仓库管理员显式移交到新设备、新修订；无移交流程时拒绝，不能删行重建绕过。卸载、移出安装范围或配置者失去管理权使绑定不再有效；已知撤权后拒绝新的写入许可；已经获准并发出的请求属在途，查询 GitHub 实际状态并保存回执，不承诺撤回。核验远端权限与调用 GitHub 不是原子操作，未知结果不重放。换绑须按预期修订以同一原子更新替换设备归属，竞争者冲突返回，核对结束前保持停用。

**任务与版本。** 受理时记录绑定修订及设备，领取和外部写入前核对仍是同一有效修订，并检查事件发起人和 PR 当前状态。任何有效规则变化使旧修订排队任务失效，重新启用不复活旧任务。旧执行停止新增副作用，已发送的写入先对账；失去租约不代表进程已经停下。服务端由可信设备身份选择队列，不按客户端指定的 workerId/仓库号授权。生产切换要求登记变更与“读有效修订并接受任务”互斥提交：#12 必须将运行登记表与任务表置于同一新 SQLite 状态库事务，禁止先跨库读取再入队。以提交顺序判断：先停用则不建任务，先受理则旧任务在领取时失效。云端 schema 3 中任务和绑定同库。

**等待期限。** 首版为首次受理时的服务端时间 + 24 小时，到点即过期；不是客户端最后在线时间，也不会因重投更新。未执行的过期任务为 rejected/skipped，保留原因；已开始执行的任务仍走 lease/unknown，不自动重跑。PR 已合并/关闭时跳过，GitHub 状态读取与外部写入非原子。

**切换与验收。** 云任务与绑定使用新 schema 3 卷，旧库保留且不迁移。设备配对后显式登记、查询或停用；不保留静态绑定配置回退。2026-11-24 的[真实双仓验收](https://github.com/xallor-ai/github-agent-channel/issues/14#issuecomment-7130728427)验证了首次升级后加仓不改 ECS、离线恢复和停用。

授权取决于配对用户：早期 write 用户探针被拒绝；随后以具备目标仓库 admin 权限的 `xallor-agent` 完成真实登记。

已下发且运行状态未知时，同设备暂停领取直至人工确认；这是执行隔离，不改变其他仓库的绑定或入队。预授权失败且从未下发的预约直接拒绝，不占住设备。
