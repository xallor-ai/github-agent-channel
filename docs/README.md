# 文档索引与维护规则

GitHub Agent Channel 是通用 GitHub 协作通道。它连接 GitHub 和用户选择的 Agent Runtime；OpenClaw 是第一个适配器。当前代码只实现分析回帖里程碑，不能据此把产品目标缩减为评论机器人。

## 先读什么

| 目的                         | 入口                                                | 文档性质                               |

| 理解代码实际如何运行         | [实现地图](implementation-map.md)                   | 当前实现事实，按源文件核对             |
| 判断哪些能力能用             | [能力与验收台账](capabilities.md)                   | 逐项状态；区分实现、本地测试、真实验收 |

| 自己部署公网 Channel 服务端  | [ECS 自建部署](ecs-setup.md)                        | 可选部署示例；已有服务可跳过           |

## 文档状态与更新责任

| 状态        | 必须写明                                  | 更新方式                                    |
| ----------- | ----------------------------------------- | ------------------------------------------- |
| 当前说明    | 适用实现、操作入口、已知限制              | 随相关代码变更同步更新                      |
| 方案/调研   | 基线、候选项、未验证点、是否已批准        | 不把建议写成现有能力；源码研究固定 revision |
| 验证记录    | 日期、提交、环境、实际命令/结果、模拟边界 | 保留历史事实；新验证另记，不覆盖旧结果      |
| 已取代/历史 | 显著提示、替代文档链接                    | 不作为当前配置或实施依据                    |

事实冲突时：当前代码/配置 schema 说明“现在怎样运行”；用户要求与 `AGENTS.md` 说明“产品应怎样发展”；两者不符记录为差距。当前操作文档服从当前实现；计划和旧记录不能覆盖源代码事实。文档中的“已通过”必须有对应证据范围。

文档各自负责一类信息：`implementation-map.md` 维护模块和调用链；`capabilities.md` 维护能力状态；`architecture.md` 维护当前边界；教程维护操作步骤；验证记录维护证据。README 只作入口与简要范围说明，避免多处重复维护同一套长教程。

每次能力变更至少核对：实现地图、能力台账、对应适配器教程/运维、配置示例、验证记录。变更实验或生产环境时分别记录，不用 schema 校验代替实际运行。
